# data-quality

## Instructions

1. Check deterministic data quality findings before deciding a variance is purely business-driven.
2. Treat duplicates, stale post-contract invoices, missing GL postings, and reconciliation gaps as possible root causes.
3. Cite the exact table, period, issue id, and SQL evidence rows for every data quality claim.
4. Explain the likely financial statement impact: revenue, COGS, vendor expense, operating expense, net income, or GL completeness.
5. Separate true business movement from data quality overstatement or understatement.
6. Recommend a concrete finance-control action such as reversing an invalid invoice, deduplicating an AP load, or reconciling subledger rows to GL.
